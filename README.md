# APEX Desktop

Professional options-intelligence terminal: paper funded or real brokerage, live (or demo) market data, TradingView charting, and a 17-layer Deep Scan that follows the workspace PDFs.

```
APEX DESKTOP/
├── docs/           Original PDFs + extracted legal, layers, contract
├── frontend/       React + TypeScript + Vite + Tailwind + Framer Motion
├── backend/        FastAPI + alpaca-py + SQLAlchemy + Redis OTP
├── infra/          secret-scan.sh
├── e2e/            (Playwright lives in frontend/e2e)
├── docker-compose.yml
└── .env.example
```

```
┌────────────┐   JWT + WS    ┌────────────┐   env keys    ┌─────────┐
│  React UI  │◄─────────────►│  FastAPI   │──────────────►│ Alpaca  │
│  Vite/TV   │               │  + worker  │               │ or demo │
└────────────┘               └─────┬──────┘               └─────────┘
                                   │
                          PostgreSQL + Redis
```

## Deep Scan layer order (implemented)

`technical` → `volume` → `candlestick_patterns` → `macd` → `rsi` → `ema` → `supertrend` → `bollinger` → `pivot_points` → `support_resistance` → `options_chain_greeks` → `volatility` → `sentiment` → `fundamentals` → `strategy` → `risk_review`

The chain and the Greeks engine are one layer (Full Document §5 is one section), so the slides the
trader actually pages through are `technical` → `options_chain_greeks` → `volatility` →
`sentiment` → `fundamentals` → `strategy` → `risk_review`.

Parameters: EMA **9/21/50/100/200**, MACD **12/26/9**, RSI **14**, SuperTrend **ATR 10 / factor 3**, Bollinger **20 SMA / 2 SD**.

## Security

- **Never commit API keys.** Load `ALPACA_API_KEY_ID`, `ALPACA_API_SECRET_KEY`, and paper/live base URLs from the environment only.
- The key ID pasted in chat (`PKMHH4RBSYR5FPIIWJRU7FHELJ`) is **BURNED**. Rotate it in the Alpaca dashboard before any production use. It is not stored in this repo.
- If Alpaca keys are missing, the options screen shows an empty state asking you to configure `.env` — it does **not** invent a fake options ladder. Offline demos only: set `ALLOW_OPTIONS_SIMULATOR=true`.
- `.env` is gitignored. `.env.example` has names only.
- `infra/secret-scan.sh` + pre-commit + CI gitleaks.

## Run locally (no Docker)

**APEX UI is pinned to `http://localhost:5173` only** (`frontend/vite.config.ts`: `host: 'localhost'`, `port: 5173`, `strictPort: true`). If Vite fails with “Port 5173 is already in use”, something else (often another project folder) is serving the wrong site — kill it, then start APEX again. Do **not** open `5174` / random ports; those are not this app.

```bash
# Free 5173 if a stale / wrong Vite is bound (macOS):
lsof -tiTCP:5173 -sTCP:LISTEN | xargs kill
# Optional: also clear an old APEX instance that hopped to 5174
lsof -tiTCP:5174 -sTCP:LISTEN | xargs kill

cp .env.example .env
# Put rotated Alpaca keys in .env for a live options chain (optional)

# Backend — always from APEX DESKTOP, with project-root .env sourced
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
set -a && source ../.env && set +a
# SQLite default if DATABASE_URL is sqlite+...
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# Frontend — ONLY from APEX DESKTOP/frontend (title must be "APEX Desktop")
cd ../frontend
npm install
npm run dev
```

Open **http://localhost:5173** — confirm the tab title is **APEX Desktop**, then splash / paper account.

**After changing Alpaca keys in `.env`:** stop and restart the API (`Ctrl+C`, then `uvicorn …` again, or `docker compose restart api`). Settings are loaded once at process start.

Demo seed (optional): `cd backend && python -m scripts.seed` → `trader` / `ApexDemo!23`.

## Run with Docker Compose

Requires a local `.env` (copy from `.env.example`). Compose wires Postgres + Redis + API + sentiment worker + nginx frontend.

```bash
cp .env.example .env
docker compose up --build
```

- UI: http://localhost:5173
- API: http://localhost:8000/health

## Substitutions vs the pitch-deck stack

| Pitch / request | What shipped | Why |
|-----------------|--------------|-----|
| `alpaca-trade-api` | `alpaca-py` + REST | User-requested official SDK; REST used so missing keys never crash import |
| TradingView Advanced widget | Free `tv.js` embed | Requested; SuperTrend is **not** a built-in widget study → computed server-side (ATR 10 / 3) |
| GPT-4 / Claude / Gemini consensus | Deterministic scan engine | No vendor AI keys in repo; same 10X weights and playbook rules; swap-in ready |
| praw / tweepy / FinBERT | Worker seed + RSS-shaped blurbs | No social API keys; worker process is the extension point |
| Plotly charts | TradingView + Deep Scan snapshots | User-specified charting |
| argon2 or bcrypt | argon2-cffi | Stronger default; tests cover hash/verify |

## Account modes

- `paper_funded`: starting balance presets $10k / $25k / $50k / $100k + custom. Paper orders fill via Alpaca paper or the demo adapter.
- `real_brokerage`: **no** `starting_balance` field in the UI (unmounted) and rejected in the API schema.

## Env

See `.env.example`. Staging/prod: set `APP_ENV=production` (disables OTP autofill), `AUTOFILL_2FA=false`, real `DATABASE_URL` / `REDIS_URL`, and rotated Alpaca keys. `SENTRY_DSN` enables Sentry on structured logs.
